# 幼児（3〜6歳）と iPad を前提にした UI の見直し

ペルソナは **3〜6歳の子ども本人** と **横にいる（あるいは、いない）親**。
「文字が読めない」「押してから話す、のような 2 段階の操作ができない」「押せるものが多いと固まる」
「画面の端を触る」「黙って考える時間が長い」を前提に、全画面を通して見直した記録です。

判定の軸は [`FIRST_RUN.md`](FIRST_RUN.md) の 5 項目と同じ
（最初の 60 秒で「できた」に到達するか／文字が読めなくても進めるか／大人がいなくても詰まらないか／
2 回目以降を遅くしないか／間違えても直せるか）。

---

## 1. 指摘されていた 3 点

### 1-1. 音声の被り

| 場所 | 何が起きていたか | 直したこと |
| --- | --- | --- |
| 正解・不正解の瞬間 | チャイム（効果音）と「せいかい！」の読み上げが同時に鳴る | 効果音が鳴り終わってから読む（`AppEnvironment.speakAfterSound`） |
| ホーム → 教科メニュー | ホームで「とけい」と読み、開いたメニューがすぐ「とけい、なにで あそぶ？」と読んで、前のを消す | ホーム側で読まない |
| 教科メニュー → 学習 | 「なんじかな？」と読んだ直後にセッションが問いかけを読んで消す | メニュー側で読まない |
| オンボーディング → ホーム | 「よろしくね！」の直後にホームが「こんにちは！」を重ねて両方消える | 挨拶をホームに 1 本化（`pendingGreeting`：「〜、よろしくね！ なにで あそぶ？」） |
| ごはんタイマー | 準備画面で読んだ台詞を「スタート」でもう一度読み、カウントダウンの音とかぶる | スタート時は読まない。結果も効果音のあとに読む |
| 結果画面 | ★の音と「よく がんばったね！」が同時 | 効果音のあとに読む |
| 読み上げ中にマイクを開く | 読み上げの途中で聞き取りを始めると、アプリが自分の声を拾う | 読み上げに完了コールバックを付け（`SpeechSynthesizing.speak(…completion:)`）、**読み終えてから** 聞き取りを始める |
| オーディオセッション | 読み上げのたびに `.playback`、聞き取りのたびに `.playAndRecord` に切り替え、聞き取り終了で毎回セッションを落としていた。切り替えのたびに読み上げの頭が欠ける | `.playAndRecord` に固定して共有（`PiyoAudioSession`）。聞き取り後もセッションを落とさない。`.measurement` モードは自動音量調整を切るので幼児の小さい声が拾えず、`.default` に変更 |

### 1-2. 音声ボタンを押さないと聞き取りが始まらない

- **切り替え UI（えらぶ／すうじ／こえ）を廃止。** タップの手段は問題ごとに 1 つに固定し（`Question.tapMode`）、
  声はその横で **勝手に** 聞いている。子どもは選択肢を押しても、キャラクターに向かって言ってもよい。
- 聞き取りは問いかけの読み上げが終わった瞬間に始まる。マイクを押すのは、
  黙ったまま聞き取りが止まったあとに「もういちど聞いてほしい」ときだけ（帯そのものがボタンになる）。
- 黙っている子には何も言わない（「もういちど いってみよう！」と急かさない）。3 回黙っていたら聞き取りを止めるだけ。
- 聞こえたが分からなかったときだけ声をかけ、読み終えたらまた聞く。3 回続いたら「タップで こたえても いいよ！」。
- **「もじを みて よむ」問題**（`answerModes` の先頭が `.voice`）は答えになる選択肢を隠して声を待ち、
  黙ったまま・聞き取れないまま続いたら、声で知らせてタップに切り替える。「タップで こたえる」ボタンでも切り替えられる。
- 古い聞き取り結果が次の問題に流れ込まないよう、問題ごとにトークンで区別する（テストあり）。
- 権限が拒否されている端末では、はじめからタップだけの画面にする。

### 1-3. 時間の入力で「40じ」が入れられる

- 数字パッド（時刻・数）を **廃止**。3〜6歳に自由な数字入力は扱えず、「40じ」「99」のような
  ありえない答えが入ってしまう。時刻も数も、選択肢（ミニ時計・数字・ものの数）と声で答える。
- `QuestionContent` / `AnswerMode.numberPad` は互換のため残しているが、子ども向け画面では選ばれない
  （`Question.tapMode` が数字入力を飛ばす）。

## 2. 自分で探して直したもの

| # | 場所 | 幼児が詰まる理由 | 直したこと |
| --- | --- | --- | --- |
| 1 | 学習画面の「×」 | システムの確認ダイアログは文字だけ（「ホームに もどる」が赤字）。読めない子は固まるか、適当に押す | キャラクターと絵つきの大きな 2 択（🏠おうちへ／▶つづける）に変更し、声でも聞く。ごはんタイマー中の「×」も同じ（15 分のごはんが押し間違いで消えないように） |
| 2 | 正解のあと | 「つぎへ」を読めない。押すまで止まる | 読み上げが終わったら自動で次へ。「つぎへ」は残す（押せば待たない）。まちがえたときは自動で進まない（もう一度やる意思が要る） |
| 3 | なぞり書き | なぞり終えたことに自分で気づけず、「できた！」を押さない | 線を引き終えるたびに判定し、十分なぞれていれば自動で進む |
| 4 | 時計の針 | 短い針と長い針を別々に合わせるのは難しい。ヒントは「ながい はりを うごかしてみよう」と言うのに、長い針だけでは時が変わらなかった | 針を本物の時計のようにつなげた。長い針を 1 周回すと短い針が 1 時間進む。短い針を直接つかんで動かすこともできる |
| 5 | ひらがな・カタカナ・アルファベットの「よむ」 | 声で答えるときだけ文字を見せていたが、読み上げが「「あ」は どれ かな？」と **答えを言っていた**（復唱するだけになる） | 「もじを みて よむ」型を追加（Lv2 以上・声が使えるときの半分）。読み上げは「この もじは なんて よむ かな？」。タップに切り替わったときだけ「「あ」は どれ かな？」に変わる（`Prompt.tapFallbackSpokenText`） |
| 6 | ごはんタイマー（15 分） | 子どもは画面に触らないので、途中で画面が暗くなる／ロックされる | 競争中と学習中は `isIdleTimerDisabled` |
| 7 | iPad の画面の端 | 下端スワイプで Dock、上端スワイプでコントロールセンターが出て、別のアプリへ行ってしまう | `defersSystemGestures(on: [.bottom, .top])` と `persistentSystemOverlays(.hidden)`。1 回のスワイプでは効かなくなる |
| 8 | 音声認識のプライバシー | README は「音声データを外部に送らない」と約束していたが、サーバー認識に送られる端末・言語があった | 端末内認識が使える場合は `requiresOnDeviceRecognition = true` |
| 9 | 波形アニメーション | 画面が出た時点で聞いていないと、あとから聞き始めても波形が動かない | 状態の変化で動かす |
| 10 | 保護者画面の広告の説明 | 「起動時にだけ表示」と書かれていたが、現状は保護者画面に入るときだけ | 文言を直した |
| 11 | ホームの挨拶 | ★の音とかぶっていた | 効果音のあとに読む |

## 3. 見て、いまは変えないもの（理由つき）

| 場所 | 気づいたこと | 変えない理由 |
| --- | --- | --- |
| オンボーディングの名前入力が 1 番目 | 3 歳にキーボードは無理。ただし「なまえは あとで」で飛ばせる | 順番の変更は [`FIRST_RUN.md`](FIRST_RUN.md) で決めた設計に反する。飛ばせる導線があるので据え置き |
| マイク許可のシステムダイアログ | 「許可」「許可しない」は読めない | OS のダイアログは変えられない。オンボーディングの最後に、使い道を見せてから出す設計のまま |
| 「なんじかな？」の選択肢がミニ時計 | 大きな時計と同じ形を探す作業になる（時刻を読んでいない） | 4 歳には「同じ形を見つける」ことが時計への入口として有効。文字の選択肢にすると読めない子が答えられない。声で答えれば本当の読みになる |
| ごはんタイマーの「たべおわった！」 | 食べる前に押せば勝手に勝てる | 親と一緒に使う前提の道具。長押しなどの関門を付けると 3 歳が本当に食べ終わっても押せない |
| 「おうちのひと」ボタン（82×60pt） | 88pt を下回る | 子どもに押してほしくないボタンなので、意図的に小さい |
| 「えいごで いってみよう」で声が使えないときの選択肢 | 出題の絵と同じ絵を選ぶだけになる | 声が使えない設定では生成しない（`allowVoice: false` で `.speakWord` を出さない）。権限拒否だけが例外で、そのときは「同じ絵を見つける」が成功体験になる |
| 3 回黙ると聞き取りを止める | もっと長く待つべきか | 聞きっぱなしはマイク表示（オレンジの点）が出続け、電池も使う。帯を押せばいつでもまた聞く |

## 4. iPad で確かめること

コードだけでは分からないので、実機で見る項目。

- 横向き iPad（1180×820）で、学習画面がスクロールなしに収まること（左：出題、右：聞き取りの帯＋選択肢 2×2）。
- iPhone 横向き（852×393）で、右列の「聞き取りの帯」と選択肢 4 つが、スクロールせずに 2 つは見えること。
- 読み上げ → 聞き取り開始の間に、アプリの声が拾われていないこと（`voiceTranscript` に問いかけの文が入らない）。
- Bluetooth スピーカー接続時に読み上げが聞こえること（`.allowBluetoothA2DP`）。
- Split View / Stage Manager で `regular` の縦積みレイアウトに崩れがないこと。
- `-uiTestMode` では正解後の自動「つぎへ」を止めている。実機では 1.4 秒（読み上げ終了後）で進む。
