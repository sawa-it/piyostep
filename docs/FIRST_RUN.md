# はじめての起動（First Run）の設計

3〜6歳向けアプリの「最初の体験」について、よくできている事例を整理し、
**ぴよステップに入れるもの／入れないもの** を決めた記録です。

対象は、アプリを初めて開いてから「自分で遊べている」と感じるまでの 1〜2 分間。
ここで離脱されると、その後の教材がどれだけ良くても届きません。

> 事例に挙げたアプリの挙動は、設計パターンの説明のために書いています。
> 各アプリの現在の実装は変わっている可能性があります。

---

## 1. 事例：うまくいっている型

### A. 説明せずに遊ばせる（チュートリアルを置かない）

Toca Boca や Sago Mini のシリーズは、開いた瞬間に触れる状態から始まります。
「使い方」の画面がなく、画面の中で動くものを押せば反応が返る。
**文字が読めない子どもに文章で説明しても届かない** ので、説明そのものを消す方向に倒しています。

### B. 最初の一手が必ず成功する

最初に出すものを、その年齢には簡単すぎるくらいにする型。
Endless Alphabet や Duolingo ABC のような文字系アプリでは、
最初の課題は「なぞる」「押す」だけで、失敗しようがない形から入ります。
**「できた」を先に渡してから難しくする**。

### C. 大人向けの入力を、子どもの導線から外す

Khan Academy Kids のように名前やアバターを決めさせる例はありますが、
どれも **飛ばせる／後から変えられる** 形です。
キーボード入力は 3〜6歳には操作できず、親が横にいないと詰まります。

### D. 声と絵だけで進む

読み上げと矢印・指のアニメーションで「次はここ」を示す型。
文字は装飾として置き、意味は音と絵で伝えます。

### E. 権限は必要になった瞬間に頼む

起動直後にマイクの許可を求めると、何のためか分からないまま拒否されます。
**マイクを使う画面で、キャラクターが「こえで こたえてみる？」と言ってから** 求める。

### F. 保護者向けを分離する（ペアレンタルゲート）

Apple の Kids Category では、外部リンク・課金・個人情報の入り口に
**子どもには解けない関門** を置くことが要件です。
設定・課金・リンクは、子どもの導線から見えない場所へ。

### G. 最初の起動では広告も課金も見せない

Kids Category の審査でも厳しく見られる部分です。
「まず遊ばせる、価値を感じてから話をする」。

### H. 案内役のキャラクターが一緒にやる

指示を出す先生ではなく、**隣で一緒にやる相手** として置く型。
「つぎは これを おして」より「いっしょに やろう！」のほうが手が動きます。

### I. 2 回目以降の起動を速くする

長いスプラッシュやロゴアニメを毎回見せない。
初回だけ丁寧に、2 回目からは即座にホーム。

### J. 行き止まりを作らない

戻る・やり直すが常にあり、どの画面からもホームに帰れる。
子どもは想定外の順番で押します。

### K. 1 画面 1 決定

選択肢を同時に 2 つ以上出さない。押せるものが多いほど固まります。

## 2. ぴよステップの現状

| 事例 | 現状 | 判定 |
|---|---|---|
| A 説明を置かない | チュートリアル画面なし。いきなりオンボーディング 3 問 | ◯ |
| B 最初の一手が成功する | **なし。** オンボ後はホームに放り出され、自分で選ばないと何も起きない | ✕ |
| C 大人向け入力を外す | **名前入力が 1 ステップ目で必須に見える**（実際は空でも進めるが、そう書いていない） | △ |
| D 声と絵だけで進む | 各ステップで読み上げあり。文字は補助 | ◯ |
| E 権限は使う瞬間に | マイクを押したときだけ要求している | ◯ |
| F 保護者を分離 | ペアレンタルゲート（3+4 などの計算）あり | ◯ |

| H キャラクターが一緒にやる | 相棒を選ばせ、ホームで迎える。ただしオンボ中の役割は薄い | △ |

| J 行き止まりがない | **オンボーディングに戻るボタンがない**（年齢を押し間違えると直せない） | △ |
| K 1 画面 1 決定 | 各ステップ 1 決定になっている | ◯ |

## 3. 入れる

優先度順。いずれも「最初の 1 分」に効くものに絞りました。

### 🔴 1. 初回起動では広告を出さない

いまは `RootView.onAppear` が無条件に走るため、**アプリを初めて開いた子どもが
最初に見るのが広告** になります。Kids Category の審査でも危うい状態です。

- プロフィールが無い＝初回のうちは広告を出さない
- オンボーディングを終えた最初のホームでも出さない（次回の起動から）

### 🔴 2. 名前入力を飛ばせるようにする

3〜6歳本人にキーボードは扱えません。横向きではキーボードが画面の半分を覆います。

- 「あとで」ボタンを付けて、押したら年齢ステップへ
- 既定の呼び名は「きみ」（すでにそうなっている）
- 「おうちのひとが あとで かえられます」と明記

### 🟠 3. 最初の 1 問を、オンボーディングの続きとして出す

ホームに放り出さず、**必ず正解できる 1 問**を相棒と一緒にやってから
ホームへ送る。最初の「できた！」を体験の中に組み込みます。

- 年齢に応じた最易問題を 1 問だけ（例：4歳なら「りんご 3こ」を数える）
- まちがえても正解に導いて必ず星が出る
- 終わったらホームへ。2 回目以降の起動では出さない

### 🟠 4. オンボーディングに戻るボタンを置く

年齢を押し間違えたら直せる。行き止まりを作らない。

### 🟡 5. 初回のホームで「どこを押すか」を 1 箇所だけ示す

「きょうの チャレンジ」に、初回だけ指のアニメーションと読み上げを付ける。
1 回押したら消える。説明文は出さない。

## 4. 入れない

見送るもの。理由をはっきりさせておき、後から蒸し返さないようにします。

| 入れないもの | 理由 |
|---|---|
| **チュートリアル画面・使い方の説明** | 文字が読めない年齢に文章は届かない。事例 A の通り、説明を消すほうが良い |
| **スキップ可能なスライドショー型の紹介** | 初回の時間を使うだけで、子どもには何も残らない |
| **ログイン・アカウント作成** | バックエンドを持たない方針。個人情報を預からないこと自体が価値 |
| **生年月日の入力** | 年齢は 3〜6 の 4 択で足りる。生年月日は個人情報の取得にあたる |
| **通知の許可要求** | 初回に出すと拒否されるうえ、幼児向けアプリで通知を送る必然性がない。毎日の声かけは保護者の仕事 |
| **アプリ内レビュー依頼** | 初回どころか当面入れない。子どもが操作してしまう |
| **初回限定のお得な課金案内** | 課金煽りを作らない方針。事例 G に反する |
| **キャラクターの長い自己紹介アニメ** | 2 回目以降に飛ばせても、初回の 30 秒を奪う。事例 I に反する |
| **難易度の自己申告（「かんたん／ふつう／むずかしい」）** | 保護者にも子どもにも判断できない。回答履歴から自動調整する仕組みが既にある |
| **チュートリアル中の強制的な操作待ち（ここを押すまで進めない）** | 押したいところを押せないのは幼児には苦痛。示すだけにして、無視しても進めるようにする |
| **音声認識のマイク許可を初回にまとめて要求** | 事例 E に反する。使う瞬間に頼む今の形を維持 |
| **保護者向けの機能紹介ツアー** | 保護者エリアに入った人はすでに探す気がある。画面を見れば分かる作りにするほうが良い |

---

## 5. 判断の軸

迷ったときはこの順で決めます。

1. **子どもが最初の 60 秒で「できた」に到達するか**
2. **文字が読めなくても進めるか**
3. **大人がいなくても詰まらないか**（キーボード・許可ダイアログ・広告を置かない）
4. **2 回目以降の起動を遅くしないか**
5. **間違えても直せるか**
